# Independent keeper candidate

The keeper has a separate sponsor identity, persistent SQLite journal, daily wei budget, gas ceiling, oracle-fee ceiling and private operations token. It does not call the API. The persistent host entrypoint accepts `keeper` with the same private sponsor/oracle/budget fields as API secrets, independently provisioned values and `/var/lib/rfq/keeper` storage. Use the systemd writer lock and separate service user. Its public edge has no keeper routes.

Each single-flight cycle reconciles signed transactions first; unresolved nonces close health and prevent new work. It reads pinned clearing state, refreshes both markets when needed, and scans up to 25 included open accounts from the independent indexer. An unhealthy or lagging indexer closes health. Simulation considers canonical funding and cross-margin state before submission. Explicit simulation reverts consume no sponsor budget; transport failures close health. At most four transactions are accepted in one cycle, with estimated gas plus a bounded buffer below the configured ceiling.

When resolution starts, account scanning and ordinary refresh/liquidation stop. The keeper submits current authenticated post-trigger reports; clearing enforces distinct timestamps and the 30-second three-sample window. Simulation rejects premature/duplicate samples. Once prices are ready, the keeper processes at most 50 accounts per cycle, re-reading the canonical cursor and stopping at finalization. Claim payments remain direct owner actions. Resolution progress does not require the indexer or API.

Health closes when no cycle has completed within 30 seconds, when a cycle fails or during shutdown. `/internal/metrics` requires the role token and returns safe status and sponsor counts; it exposes no raw provider errors, signed bodies or keys. Shutdown waits for the active cycle; abrupt host termination is recovered through the journal and sponsor reconciliation.

`scripts/keeper-e2e.mjs` stops the API and uses linked clearing, a local fee-charging Pyth adapter and an independent funded signer to verify bankruptcy, journal restart, resolution sampling and crystallization. Before scanning liquidations, the keeper simulates the permissionless objective maker-capital trigger; a normal revert creates no sponsor transaction, while a proved floor/stress breach enters resolution and stops further mutations. This is local execution evidence. Production oracle availability, independent host/key provisioning, monitored budgets and sustained outage qualification remain external prerequisites.
