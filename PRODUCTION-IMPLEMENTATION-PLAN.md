# Production implementation plan

2026-09-15. Execution baseline: `6c04310` and existing Cloudflare changes. Findings and rationale: `REPO-CONTEXT-AND-PRODUCTION-REVIEW-2026-09-15.md`.

Status vocabulary: pending, implementing, locally verified, externally verified. Local verification does not satisfy independent audit, provisioning or capital qualification.

## Implementation decisions

- Preserve the single settlement proxy and append-only storage. Keep the 21,000-byte gate; move arithmetic and explicitly scoped bookkeeping into linked libraries when needed. Treat mutating modules as implementation authority and review their typed storage boundaries.
- Use persistent-volume Linux hosts for the initial financial runtime. Cloudflare remains the public edge; ephemeral Containers must reject startup for financial workloads until a transactional external journal is implemented. This avoids introducing a distributed database solely to ship the testnet.
- Provision production approvers independently. A monolithic local/testnet bootstrap is explicitly a disposable profile, never production key custody.
- Implement native Base USDC deposits first. Cross-chain routes remain disabled outside the simulator until a reviewed adapter exists.
- Freeze incident funding and positions at resolution; reject financial mutations while claims are crystallized. Do not invent an unsigned oracle fallback.
- Mainnet tooling must fail closed until an immutable reviewed manifest, real provider/key provisioning, independent reviews and qualification evidence exist.

## Validation strategy

Write targeted regressions for financial and security defects before or with each repair. Use deterministic local RPC fixtures for indexer crash boundaries and the OP EVM for contract accounting. Run narrow affected suites during implementation, then the complete `npm test` and storage/bytecode gate after integrating contract changes. Preserve secret-free reports and record exact source/build identities. Never use mock success as live wallet/oracle/venue qualification.

## External dependencies and release controls

Repository implementation can proceed immediately. Independent auditors, separate hardware-key custodians, persistent host/provider accounts, Access identities, monitored RPC/oracle agreements, venue capital/fencing, legal review and sustained observation are real external prerequisites. They remain explicit pending evidence, not boxes completed by generated code.

Deploying new real-capital contracts or enabling mainnet order submission requires the completed candidate and concrete deployment review. Existing testnet disposable profiles may be exercised within their documented caps, but no test changes should silently upgrade deployed contracts or place venue orders.
